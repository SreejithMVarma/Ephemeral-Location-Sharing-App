# Changes — Backend & Frontend

This file summarizes the code changes made across the backend and mobile frontend as part of the full-map tracking rollout and follow-up maintenance.

## Backend

- Fixed Poetry dependency resolution:
  - Updated `[tool.poetry.dependencies]` in `apps/backend/pyproject.toml` to align with the lock: `fastapi = "^0.116.2"` and `starlette = "^0.48.0"`.
  - Regenerated `apps/backend/poetry.lock` and updated the Docker build to copy `poetry.lock` before install and use `poetry install --no-root` for reproducible builds.
  - Dockerfile change: copy `poetry.lock` and install from lockfile (see `apps/backend/Dockerfile`).
  - Commit: `92b9109` — "Fix backend Poetry resolution" (pushed to `main`).

- New and modified backend services:
  - Added `apps/backend/src/services/pubsub_broadcaster.py` (Redis pub/sub publishing helper).
  - Added `apps/backend/src/services/viewport_service.py` (in-memory viewport subscription registry).
  - Updated `apps/backend/src/services/websocket_service.py` to support viewport subscribe/unsubscribe events, rate-limited location handling, and Redis pub/sub forwarding.
  - Metrics: added viewport subscription/unsubscription counters in `apps/backend/src/infrastructure/metrics.py`.
  - Lifespan hooks updated in `apps/backend/src/main.py` to start/stop Redis listener.

- Tests:
  - Added `apps/backend/tests/services/test_viewport_service.py` covering subscription logic.

## Mobile frontend (Flutter)

- Full Map (Mapbox) integration:
  - Added a native Mapbox implementation using `mapbox_maps_flutter`.
  - New file: `apps/mobile/lib/features/map/presentation/full_map_view.dart` — sets up clustered `GeoJsonSource`, cluster layers, and live updates.
  - Map token initialized in `apps/mobile/lib/main.dart` from `MAPBOX_TOKEN`.
  - Commit: `37645a4` — "Implement Mapbox full map tracking" (pushed to `main`).

- Session & websocket integration:
  - Session state extended (`apps/mobile/lib/features/session/application/session_state.dart`) to include `isCreatedByMe` / `adminId` so the session creator is the implicit admin.
  - Websocket/radar message parsing and sync improved (`radar_message.dart` and websocket service providers).

- Dependency & tooling changes:
  - Added `path_provider` to `apps/mobile/pubspec.yaml` for session logging.

- Lint / analyzer cleanup and minor UI fixes:
  - Fixed `use_build_context_synchronously` by caching `ScaffoldMessenger.of(context)` before async clipboard calls in `apps/mobile/lib/features/session/presentation/entry_screen.dart`.
  - Replaced deprecated `Colors.black.withOpacity(...)` with `withValues(alpha: ...)` in `apps/mobile/lib/features/session/presentation/qr_scanner_screen.dart`.
  - Removed unused imports and adjusted doc comments to silence analyzer warnings in various session screens.

## Manual testing

Below are quick manual test instructions for local verification of the backend and the mobile frontend.

Backend (local, quick):

- Prerequisites: `python 3.12`, `poetry`, and a running Redis instance (or Docker).

- Run with Poetry:

```bash
cd apps/backend
poetry install --only main
poetry run uvicorn src.main:app --host 0.0.0.0 --port 8000 --reload
```

- Health check (once running):

```bash
curl http://localhost:8000/health
```

- Run the backend tests for viewport subscriptions:

```bash
cd apps/backend
poetry run pytest apps/backend/tests/services/test_viewport_service.py -q
```

- Run via Docker (recommended for CI parity):

```bash
# Ensure Redis is reachable. Start a local Redis for testing:
docker run -d --name redis-local -p 6379:6379 redis:7

# Build the backend image (context is repo root):
docker build -f apps/backend/Dockerfile -t ephemeral-radar-backend:local apps/backend

# Run the image (adjust REDIS_URL as needed):
docker run --rm -e REDIS_URL=redis://host.docker.internal:6379 -p 8000:8000 ephemeral-radar-backend:local
```

Frontend (Flutter, emulator or device):

- Prerequisites: Flutter SDK, Android/iOS emulator or device.

- Run analyzer and get packages:

```bash
cd apps/mobile
flutter pub get
flutter analyze
```

- Run on device (debug):

```bash
flutter run
```

- Build debug APK (Android):

```bash
flutter build apk --debug --no-shrink
```

Functional checks to perform in the app:

- Create a new session in the app (session creator is the implicit admin).
- On a second device or emulator, join the session using the share link or QR code.
- On the map screen (`Full Map`), verify:
  - The map centers and displays clustered points when multiple participants are nearby.
  - As participants move, their markers update in real time and clusters split/merge appropriately.
  - Creator/admin badge appears for the session creator.
- If you want to simulate multiple participants quickly, run multiple emulators or use the session location logger to replay a recorded trace.
